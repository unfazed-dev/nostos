# nostos-swift

UniFFI bindings exposing `nostos-client`'s `SyncClient<SqliteStorage>` to Swift
(iOS + macOS).

**Status: v0.1 alpha, not published.** The live iOS-simulator round-trip is
proven (see *Verify*), but SPM `.binaryTarget` linking of the xcframework is the
next increment — today `Package.swift` declares the target *shape*, and the
working harness links `libnostos_swift.a` directly. See
[A11](../../docs/plans/nostos-completion-assessment-2026-07-29.md).

## What you get

A single `NostosClient` class, generated by UniFFI from [`src/lib.rs`](src/lib.rs):

| method | signature | notes |
|---|---|---|
| `init(url:token:dbPath:)` | `throws` | opens SQLite; **no** network I/O |
| `connect()` | `throws` | opens the WebSocket |
| `subscribe(table:)` | `throws` | starts the live replication run loop |
| `disconnect()` | `throws` | stops the run loop **without wiping local state** (push sleep; ADR-0037) |
| `resume()` | `throws` | reopens the loop from the durable checkpoint (push wake) |
| `watch(table:)` | `-> AsyncStream<String>` | reactive PUSH — initial snapshot + every change tick (no polling); Swift-native port of Flutter's / Kotlin's `watch`. Overloads the low-level `watch(table:sink:)` |
| `write(table:op:pk:payloadJson:)` | `throws -> UInt64` | `op` ∈ `upsert` / `delete` / `patch` |
| `query(sql:)` | `throws -> String` | JSON array of rows from on-device SQLite |
| `checkpoint()` | `throws -> UInt64` | durable LSN — the resume point on reconnect |

All calls are **blocking** (the Rust side owns a tokio runtime and `block_on`s),
so call them off the main actor.

```swift
import Nostos

let nostos = try NostosClient(
    url: "ws://127.0.0.1:8080/sync",   // the iOS sim shares the host's localhost
    token: nil,
    dbPath: NSTemporaryDirectory() + "cairn.db"
)
try nostos.connect()
try nostos.subscribe(table: "tasks")

_ = try nostos.write(table: "tasks", op: "upsert", pk: "t1",
                    payloadJson: #"{"title":"Walk dog"}"#)
let rows = try nostos.query(sql: "SELECT * FROM tasks")   // JSON string
let lsn  = try nostos.checkpoint()
```

Reactive watch — a true Rust→Swift **push** (no polling), surfaced as the
Swift-native `AsyncStream`:

```swift
// Fresh full-table snapshot now, and again after every remote apply / local write.
let stream = nostos.watch(table: "tasks")
for await snapshot in stream {        // snapshot == JSON array-of-objects String
    render(snapshot)
}                                      // Task.cancel / `break` finishes the stream
```

Unlike Android, **the iOS simulator shares the host's loopback**, so
`127.0.0.1` reaches a host-side server directly — no `10.0.2.2` remap (that is
Android-emulator-only).

`write` returns when the write is durable in the local outbox, **not** when the
server acks it — see
[ADR-0027](../../docs/adr/0027-write-outcome-visibility-in-the-client-sdk.md).

## Build

```bash
cd sdk/nostos_swift

# 1. the Rust staticlib
cargo build --release                                  # host (macOS)
cargo build --release --target aarch64-apple-ios-sim   # simulator
cargo build --release --target aarch64-apple-ios       # device

# 2. regenerate the Swift bindings (committed under swift-sources/).
#    Needs the standalone CLI: cargo install uniffi-bindgen-cli --version 0.28
#    (verify: `uniffi-bindgen --version` → uniffi-bindgen 0.28.3)
cargo build --lib          # host .dylib — bindgen reads its symbols
uniffi-bindgen generate \
  --library target/debug/libnostos_swift.dylib \
  --language swift --out-dir swift-sources

# 3. typecheck the generated Swift + the AsyncStream facade without linking.
#    The `-Xcc -fmodule-map-file` flag is REQUIRED: without it, swiftc does not
#    import the `nostos_swiftFFI` C module, `canImport(nostos_swiftFFI)` is false,
#    and every FFI type (`RustBuffer`, `ForeignBytes`, …) is undefined. (The
#    bare `swiftc -typecheck -I swift-sources …` form previously documented
#    here fails with 100+ errors under Xcode 16+ / Swift 6; the modulemap flag
#    is the fix.)
swiftc -typecheck -I swift-sources \
  -Xcc -fmodule-map-file=swift-sources/nostos_swiftFFI.modulemap \
  swift-sources/nostos_swift.swift \
  swift/Sources/Nostos/Nostos.swift
```

`swift-sources/` (`nostos_swift.swift`, `nostos_swiftFFI.h`, `.modulemap`) is
**gitignored** — a regenerated build artifact. Refresh it with step 2 after any
`src/lib.rs` change to the FFI surface.

## Verify

```bash
# from the repo root, with any iPhone/iPad simulator booted
xcrun simctl boot "iPhone SE (3rd generation)"   # or any device
make sdk-e2e swift
```

`ios-test/build.sh` spawns the shared Rust spine, discovers its port, injects it
into the app via `SIMCTL_CHILD_NOSTOS_E2E_PORT`, and gates exit 0 on a real
PUSH + ECHO round-trip.

The simulator is **discovered, not hardcoded** — the script picks the first
booted iPhone/iPad from `simctl list devices booted`. Pin one with
`NOSTOS_SIM_UDID=<udid>`. (It filters to iPhone/iPad on purpose: a booted
watchOS/tvOS sim handed to `xcodebuild -sdk iphonesimulator` would fail with a
misleading error.)

## Ceiling (ponytail)

- **`Package.swift` is a shape declaration, not a working SPM product.** It
  exposes a regular `.target` over the generated sources; the shipping form is
  `.binaryTarget(path: "../xcframework/Nostos.xcframework")`. Build the
  xcframework with `cargo build --release` for the macOS + iOS targets, then
  `xcodebuild -create-xcframework`.
- **Blocking, not `async`.** UniFFI async would make these `async throws`;
  upgrade at the `#[uniffi::export]` seam.
- **One table per client**, and **`query` returns JSON**, not typed rows — same
  deliberate FFI narrowing as the Kotlin SDK.
- **No CocoaPods/SPM release.** Packaging is A11.
