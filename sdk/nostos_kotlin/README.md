# nostos-kotlin

UniFFI bindings exposing `nostos-client`'s `SyncClient<SqliteStorage>` to Kotlin / Android.

**Status: v0.1 alpha, not published to Maven Central.** The live Android
round-trip is proven end to end (see *Verify* below), but this package ships as
source in the monorepo — there is no `implementation("run.nostos:nostos-kotlin")`
coordinate yet. See [A11 in the completion assessment](../../docs/plans/nostos-completion-assessment-2026-07-29.md).

## What you get

A single `NostosClient` object, generated by UniFFI from
[`src/lib.rs`](src/lib.rs) into `uniffi.nostos_kotlin`:

| method | signature | notes |
|---|---|---|
| constructor | `NostosClient(url, token, dbPath)` | opens SQLite; **no** network I/O |
| `connect()` | `Unit` | opens the WebSocket |
| `subscribe(table)` | `Unit` | starts the live replication run loop |
| `disconnect()` | `Unit` | stops the run loop **without wiping local state** (push sleep; ADR-0037) |
| `resume()` | `Unit` | reopens the loop from the durable checkpoint (push wake) |
| `write(table, op, pk, payloadJson)` | `ULong` | `op` ∈ `upsert` / `delete` / `patch`; returns the outbox id |
| `query(sql)` | `String` | JSON array of rows from on-device SQLite |
| `checkpoint()` | `ULong` | durable LSN — the resume point on reconnect |
| `registerPushToken(platform, token)` | `Unit` | `platform` ∈ `fcm` / `apns` / `webpush`; `POST /push-tokens`, same JWT as the sync connection (ADR-0037) |
| `deregisterPushToken(token)` | `Unit` | `DELETE /push-tokens/{token}`; `signOut` calls it for session-registered tokens |

Every method throws `NostosException` on failure. All calls are **blocking**:
the Rust side owns a multi-thread tokio runtime and `block_on`s, so call them
off the main thread (`Dispatchers.IO`).

```kotlin
import uniffi.nostos_kotlin.NostosClient

val nostos = NostosClient(
    url = "ws://10.0.2.2:8080/sync",   // 10.0.2.2 = the host, from an emulator
    token = null,
    dbPath = "${context.filesDir}/cairn.db",
)
nostos.connect()
nostos.subscribe("tasks")

nostos.write("tasks", "upsert", "t1", """{"title":"Walk dog"}""")
val rows = nostos.query("SELECT * FROM tasks")   // JSON string
val lsn = nostos.checkpoint()
```

`write` returns as soon as the write is durable in the local outbox — **not**
when the server acks it. That is the offline-first contract: the write survives
process death and replays on reconnect. See
[ADR-0027](../../docs/adr/0027-write-outcome-visibility-in-the-client-sdk.md)
for how write outcomes surface.

## Push notifications (ADR-0037)

Push is a **doorbell**, not a data channel: a data-only `{table, lsn}` hint
wakes the app, and the sync connection — never the push rail — delivers the
rows, resuming from the durable LSN checkpoint. Register the FCM token with
the server and re-wake sync on arrival:

```kotlin
// Whenever the OS hands you a (possibly rotated) token:
//   FirebaseMessaging.getInstance().token / onTokenRefresh
nostos.registerPushToken("fcm", fcmToken)   // "apns"/"webpush" accepted too
// signOut() deregisters session-registered tokens automatically (best-effort).
```

Nothing here adds a plugin dependency — `registerPushToken` is a plain REST
call (`POST /push-tokens`, same JWT the client uses for `/sync`); FCM
registration stays the app's own. A non-`204` throws `NostosException`
carrying the status + body. Tokens registered before a process restart are
not auto-deregistered on a later sign-out — the server prunes them when FCM
reports the token dead (`UNREGISTERED` / APNs 410).

**Wake entry** — what your FCM handler (`FirebaseMessagingService`, or a
data-only message handler) does:

```kotlin
// Paused app (a live NostosClient whose loop was disconnect()-ed): the delta
// past the durable checkpoint applies on reconnect.
nostos.resume()

// Killed app: no handle survives. Cold-open the SAME dbPath — the durable
// checkpoint lives in the SQLite file, so this is a delta catch-up, not a
// resync:
val nostos = NostosClient(url, token, "$filesDir/cairn.db")
nostos.connect()
nostos.subscribe("tasks")   // delta applies from the checkpoint; then disconnect()
```

Verified claims: the warm path (`disconnect()` → `resume()` applies the delta
from the checkpoint, no loss) is pinned by nostos-client's
`disconnect_then_resume_applies_delta_from_checkpoint_without_loss` and this
crate's `disconnect_keeps_local_state_queryable_and_resume_reenters`; the
cold path's premise — the checkpoint survives process death on disk — is
pinned by nostos-client's `checkpoint_survives_drop_and_reopen_on_disk`
(ADR-0016).

## Build

```bash
cd sdk/nostos_kotlin

# 1. the Rust cdylib for each Android ABI (NDK linkers wired in .cargo/config.toml)
cargo build --release --target aarch64-linux-android
cargo build --release --target x86_64-linux-android      # emulator

# 2. regenerate the Kotlin bindings (committed under kotlin-sources/).
#    Needs the standalone CLI: cargo install uniffi-bindgen-cli --version 0.28
#    (verify: `uniffi-bindgen --version` → uniffi-bindgen 0.28.3)
cargo build --lib          # host .dylib — bindgen reads its symbols
uniffi-bindgen generate \
  --library target/debug/libnostos_kotlin.dylib \
  --language kotlin --out-dir kotlin-sources
```

Those are the exact commands `scripts/run-live-e2e.sh` runs (steps 1–2), so they
are covered by `make sdk-e2e kotlin`.

`kotlin-sources/uniffi/nostos_kotlin/nostos_kotlin.kt` is **committed** — it is
the reviewable artifact, and regenerating it should produce no diff.

## Verify

```bash
# from the repo root, with an emulator on port 5556 (see the note below)
make sdk-e2e kotlin
```

This spawns the shared Rust spine host-side, threads its port into the test APK
via `-PnostosPort=`, and gates on a real PUSH + ECHO round-trip through
`ws://10.0.2.2:<port>/sync`.

**The emulator must be `nostos_api34` on port 5556.** `scripts/run-live-e2e.sh`
hardcodes `EMU_SERIAL=emulator-5556` and boots that AVD itself if it is absent —
so booting the same AVD on the default port 5554 holds its lock and deadlocks
the harness's own boot. Sibling emulators on other ports are fine; the harness
scopes gradle with `ANDROID_SERIAL`.

```bash
~/Library/Android/sdk/emulator/emulator -avd nostos_api34 \
  -no-window -no-audio -no-boot-anim -gpu swiftshader_indirect -port 5556
```

## Ceiling (ponytail)

- **Blocking API, not `suspend`.** UniFFI's async support would let these be
  `suspend fun`s; today the Rust side owns the runtime and blocks. Upgrade at
  the `#[uniffi::export]` seam in `src/lib.rs`.
- **One table per client.** `subscribe` replaces the prior subscription rather
  than multiplexing. Multi-table is the
  [provider-dashboard plan](../../docs/plans/nostos-provider-dashboard-multitable.md).
- **`query` returns a JSON string**, not typed rows — deliberate, so the FFI
  surface stays one primitive wide. Deserialize on the Kotlin side.
- ~~**No Maven coordinate.**~~ Resolved 2026-09-21 — `android/build.gradle.kts`
  carries `maven-publish` + `signing` and a `centralBundle` task. See below.

## Publishing to Maven Central

There is no official Gradle plugin for the Central Publishing Portal
(checked 2026-09-21 against central.sonatype.org), so this build stays on stock
`maven-publish`: it stages the artifacts into a local Maven layout and zips
them into one uploadable bundle.

```bash
# No JAVA_HOME juggling. Gradle 9.7.1 runs on any JDK 17–26 and AGP 9.4
# needs only JDK 17+, so the system default works. (This read "JDK 17–21
# required" while the module was pinned to Gradle 8.9, which tops out at
# JDK 22 — the toolchain bump removed the constraint, not a workaround.)
cd sdk/nostos_kotlin/android
./gradlew centralBundle \
  -PnostosGroupId=io.github.<your-github-username> \
  -PsigningInMemoryKey="$(gpg --armor --export-secret-keys <KEYID>)" \
  -PsigningInMemoryKeyPassword=<passphrase>
# → android/build/distributions/nostos-kotlin-0.2.0-central-bundle.zip
```

Then upload that zip to `https://central.sonatype.com/api/v1/publisher/upload`
with a Portal bearer token. That step needs the account, a verified namespace
and a GPG key — all operator-owned, none of them in this repo.

**Namespace, the cheap path:** signing up for the Portal *with a GitHub
account* auto-verifies `io.github.<that username>` — no domain, no DNS TXT
record. `nostosGroupId` defaults to `io.github.unfazed-dev` for exactly that
reason; override it the day a real domain exists.

Signing is off unless `-PsigningInMemoryKey` is passed, so `assembleRelease`
and CI stay green on a machine with no GPG. Verified 2026-09-21: the task
produces a 30-file bundle (aar + sources + javadoc + pom, each with
md5/sha1/sha256/sha512) in the layout Central expects.

`centralBundle` depends on `verifyAar`, which fails the build if the release
`.aar` ships an empty `classes.jar`. That is not hypothetical: the AGP 9
upgrade moved Kotlin compilation to the `kotlin` source set, and the module's
`java.srcDirs("../kotlin-sources")` silently stopped feeding the compiler — a
3.4 MB `.aar` with the `.so` intact, 0 classes, and a green build. Run
`./gradlew verifyAar` on its own after any source-set or AGP change.
