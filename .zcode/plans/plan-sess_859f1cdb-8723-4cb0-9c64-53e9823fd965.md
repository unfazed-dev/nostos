## Summary

Turn the nostos_flutter example into a comprehensive, production-quality booking application: providers with configurable rates (hourly / flat-fee / subscription), clients managing bookings, availabilities, appointments, **invoices with auto-calculated billing**, and a **realtime chat interface** — all local-first and reactive via nostos sync, backed by Supabase. Architecture: stacked MVVM + Material 3 (per your decision), applying the stacked-kit-designer methodology (anti-slop blacklist, responsive form-factor thinking, motion enum) with real compileable code.

---

## Critical constraint discovered (shapes the schema)

The Rust write-back (`crates/nostos-infra/src/write_back.rs:774`) binds JSON values by **shape-inference, not a column type map**. There is no `Decimal`/NUMERIC variant — `f64`→FLOAT8 only, `i64`→INT8 only.

**Design response:** all new money/rate columns use **BIGINT** (cents) — native `i64`→`int8` bind match, guaranteed safe. Decimal hours are avoided: billing computes in integer minutes × integer cents-per-hour. No NUMERIC, no INT4, no FLOAT needed anywhere. This sidesteps the bind bug entirely.

```sql
  ADD COLUMN IF NOT EXISTS hourly_rate_cents BIGINT DEFAULT 0,           -- cents per hour
  ADD COLUMN IF NOT EXISTS flat_rate_cents   BIGINT DEFAULT 0,           -- one-off service fee
  ADD COLUMN IF NOT EXISTS subscription_rate_cents BIGINT DEFAULT 0,     -- recurring monthly
  ADD COLUMN IF NOT EXISTS bio TEXT,
  ADD COLUMN IF NOT EXISTS avatar_color TEXT DEFAULT '#2E6FDB';
```

**`invoices`** — add billing detail columns (rate snapshot + line breakdown):
```sql
ALTER TABLE invoices
  ADD COLUMN IF NOT EXISTS provider_id   UUID    REFERENCES providers(id) ON DELETE SET NULL,
  ADD COLUMN IF NOT EXISTS line_type     TEXT    DEFAULT 'hourly',   -- 'hourly'|'flat'|'subscription'
  ADD COLUMN IF NOT EXISTS rate_cents    BIGINT  DEFAULT 0,           -- rate snapshot at issue time
  ADD COLUMN IF NOT EXISTS hours_min     BIGINT  DEFAULT 0,           -- minutes billed (from appointment duration)
  ADD COLUMN IF NOT EXISTS description   TEXT,
  ADD COLUMN IF NOT EXISTS due_at        TIMESTAMPTZ,
  ADD COLUMN IF NOT EXISTS paid_at       TIMESTAMPTZ;
```

**NEW `messages` table** (realtime chat — confirmed 2026 local-first best practice: synced table = realtime stream):
```sql
CREATE TABLE IF NOT EXISTS messages (
  id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  provider_id UUID NOT NULL REFERENCES providers(id) ON DELETE CASCADE,
  client_id   UUID NOT NULL REFERENCES clients(id) ON DELETE CASCADE,
  sender_type TEXT NOT NULL CHECK (sender_type IN ('provider','client')),
  sender_id   UUID NOT NULL,
  body        TEXT NOT NULL,
  created_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
  read_at     TIMESTAMPTZ
);
CREATE INDEX IF NOT EXISTS idx_messages_thread ON messages (provider_id, client_id, created_at);
```

## Phase 3 — Billing calculation engine

New file: `lib/services/billing_service.dart`

A pure Dart service that calculates invoice amounts client-side (local-first — no server round-trip needed):

```dart
class BillingService {
  /// Returns the amount in cents for an appointment based on provider's rate.
  static int calculateAmount({
    required Provider provider,
    required int durationMinutes,
  }) {
    switch (provider.rateType) {
      case 'hourly':
        // (duration_min * hourly_rate_cents) / 60, rounded to nearest cent
        return (durationMinutes * provider.hourlyRateCents / 60).round();
      case 'flat':
        return provider.flatRateCents; // one-off, duration-independent
      case 'subscription':
        return provider.subscriptionRateCents; // monthly recurring
      default:
        return 0;
    }
  }

  /// Build the full invoice payload with rate snapshot + line detail.
  static Map<String, dynamic> buildInvoicePayload({...}) => {...};
}
```

Key design: the rate is **snapshotted** into the invoice at creation time (`rate_cents`) so historical invoices never change when a provider updates their rate. This is the canonical billing pattern (confirmed by DBA-SE + dev.to research).

### ViewModel pattern (per view)
```dart
class ProvidersViewModel extends BaseViewModel {
  final NostosDatabase _db;
  List<Provider> _providers = [];
  StreamSubscription? _sub;

  ProvidersViewModel(this._db);

  void init() {
    _sub = _db.watchMapped<Provider>('SELECT * FROM providers', Provider.fromRow)
        .listen((rows) { _providers = rows; notifyListeners(); });
  }

  List<Provider> get providers => _providers;
  // ... addProvider, updateRate, etc.

  @override
  void dispose() { _sub?.cancel(); super.dispose(); }
}
```

### Design methodology applied (stacked-kit-designer anti-slop blacklist)
- **No purple gradients** → Material 3 `colorSchemeSeed: Color(0xFF2E6FDB)` (the app's established blue)
- **No emoji as icons** → real Material `Icons.*` throughout
- **Configured MaterialApp theme** → full `ThemeData` with `useMaterial3: true`, seeded color scheme
- **Flat surfaces** → no default `Card` elevation; explicit `Material` with `elevation: 0`
- **Responsive layout** → NavigationRail (desktop, `width > 600`) vs BottomNavigationBar (mobile) — genuine adaptive, not stretched phone
- **Motion: rise-in** → list entrances with `flutter_animate` `.fadeIn().slideY()` (staggered)
- **ListView.builder** everywhere (not `ListView(children: ...)`) for performance with large lists

### Feature details

**Providers page**: list with rate badges (hourly $X/hr, flat $Y/visit, sub $Z/mo), edit dialog to set/change rates + rate_type. Provider detail shows availabilities + upcoming appointments.

**Clients page**: list with contact info, notes. Client detail shows their appointments + invoices + chat threads.

**Availabilities page**: list of recurring windows grouped by provider, with day/time display. Add/edit availability.

**Appointments page**: create appointment (pick provider + client + time + duration). On creation, optionally auto-generate an invoice (billing engine calculates from provider rate × duration). Status workflow: confirmed → completed/cancelled.

**Invoices page**: create invoice linked to an appointment — **amount auto-calculated** from the provider's rate type and the appointment duration. Shows line breakdown (rate, hours, line type). Status: issued → paid. Invoice detail card shows the full billing breakdown.

**Chat page** (NEW): conversation list (provider+client pairs) → message thread view. Messages stream reactively via `watchMapped<Message>('SELECT * FROM messages WHERE provider_id=... AND client_id=... ORDER BY created_at')`. Send bar at bottom writes via `db.write(table: 'messages', op: 'upsert', ...)`. Messages appear in realtime on both sides as they sync through nostos.

## Out of scope (deliberately)
- **No stacked_kit** — doesn't exist on pub.dev or locally (verified). Using Material 3 + cupertino idioms instead, per your decision.
- **No write-back Rust changes** — the BIGINT/TEXT/UUID/TIMESTAMPTZ-only schema sidesteps the INT4/NUMERIC bind limitation. No `SqlValue::Decimal` needed.
- **No server/nostos-core changes** — the sync engine already handles arbitrary tables. Adding `messages` to the publication + `NOSTOS_WRITE_TABLES` is config-only.
- **No auth/multi-tenancy** — single-tenant demo (matches current v1 scope). The `ponytail:` comment on the schema notes per-provider `where_sql` partitioning as the upgrade path.
- **No payment processing** — invoices track status (issued/paid) but don't integrate Stripe/PayPal. That's a separate `nostos-cloud` concern.
